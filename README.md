Это продолжение проекта [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android) — Android-порта [TgWsProxy от Flowseal](https://github.com/Flowseal/tg-ws-proxy). Оригинальный форк перестал обновляться, а в нём остался неприятный баг: прокси отваливался каждые 10–15 минут и оживал только после ручного перезапуска.

Цель этого репозитория — исправить накопившиеся ошибки, подтягивать изменения из оригинального TgWsProxy и поддерживать приложение дальше.

---

## Что это и зачем

Приложение поднимает на телефоне локальный MTProto-прокси. Telegram подключается к нему, а прокси уже сам доставляет трафик до серверов Telegram через WebSocket (TLS) — напрямую или через Cloudflare. Никаких сторонних серверов и VPN: всё работает на самом телефоне.

```text
Telegram → 127.0.0.1:1443 (MTProto) → TG WS Proxy → WSS напрямую / через Cloudflare → дата-центр Telegram
```

Движок написан на **Rust**, интерфейс — на **Kotlin + Jetpack Compose** (Material 3).

## Что изменено в этом форке

### 1.2.4 — своё приложение, батарея и патчи оригинала

**Батарея.** Главная причина расхода — фоновая работа, которая не останавливалась никогда:
- Пул заготовленных соединений **засыпает**, если Telegram 2 минуты не открывал новых соединений, и просыпается при следующем подключении. Раньше он пересоздавал соединения каждые 2 минуты круглосуточно.
- Медиа-соединения заготавливаются по требованию, а не сразу для всех дата-центров.
- **«Умный» wakelock:** держится, только пока Telegram что-то передаёт, и отпускается в простое.
- TCP keepalive — раз в 120 с вместо 30 с, ping моста — раз в 60 с вместо 30 с.
- При выключенном экране уведомление не обновляется, статистика опрашивается реже.
- Логи читаются только при открытом приложении (раньше logcat читался в фоне постоянно), подробные логи движка — только если включён фильтр «Debug».

**Стабильность и патчи из [TgWsProxy](https://github.com/Flowseal/tg-ws-proxy):**
- Мёртвые соединения в пуле теперь распознаются до того, как их получит Telegram (аналог `_is_stale` из оригинала). Раньше такое соединение «висело», и помогал только перезапуск.
- Самовосстановление: если несколько подключений подряд не нашли рабочего маршрута, прокси сам сбрасывает блокировки и пул.
- Backoff для TCP-fallback: прямой TCP до дата-центров не пробуется заново на каждом подключении (оригинал, 50c980e).
- Для обычных (не медиа) соединений используется только основной домен `kwsN` (оригинал).
- Пул CF worker: исправлено пополнение (после первого использования он больше не пополнялся) и закрытие при остановке (оригинал, #1411).

**Остальное:**

- **Отдельное приложение** (`io.github.alexingin.tgwsproxy`) с собственной подписью. Обновления приходят из этого репозитория, а не от автора оригинального порта.
- **Переключатель «Не давать телефону засыпать»** в настройках. Если выключить, расход батареи заметно меньше, но фоновая работа может стать менее стабильной ([#253](https://github.com/amurcanov/tg-ws-proxy-android/issues/253)).
- **Android 5–6:** нативная библиотека для arm64 теперь собирается под Android 5.0. Должно исправить вылет при запуске прокси ([#258](https://github.com/amurcanov/tg-ws-proxy-android/issues/258)).
- **Английский интерфейс:** переведены оставшиеся строки, которые были зашиты по-русски ([#167](https://github.com/amurcanov/tg-ws-proxy-android/issues/167)).
- Релизные APK больше не отладочные: они меньше весят и реже пугают Play Защиту.

### 1.2.3-stable — стабильность в фоне

Главное: прокси больше не «засыпает».

- **Не блокирует дата-центр на час из-за одного сбоя.** Раньше один таймаут подключения (погас экран, переключился Wi-Fi ↔ LTE, связь моргнула) отправлял DC в чёрный список на 3600 секунд. Теперь — на 30 секунд, а блокировка «все домены ответили 302» живёт 10 минут вместо «до перезапуска».
- **Живой пул соединений.** Пул заготовленных соединений перестал умирать, когда все соединения протухали одновременно: обслуживающая задача теперь работает постоянно и сама дотягивает пул (по образцу актуального TgWsProxy).
- **Реакция на смену сети и пробуждение.** При переключении сети или включении экрана после сна прокси сбрасывает накопленные блокировки и старые соединения — по сути мягкий перезапуск без обрыва текущих соединений Telegram.
- **Сторожок.** Если локальный порт перестаёт отвечать, прокси перезапускается сам.
- **Восстановление слушающего сокета** вместо холостого цикла при ошибках.
- **Сборка APK через GitHub Actions** — больше не нужен Android Studio, чтобы собрать приложение.

## Установка

1. Скачайте APK со [страницы релизов](https://github.com/Alexingin/tg-ws-proxy-android/releases):
   - `arm64` — для любого современного телефона;
   - `universal` — если не уверены или устройство старое (32-бит).
2. **Удалите версию от amurcanov, если она стоит.** Это теперь разные приложения, и они будут мешать друг другу за один и тот же порт.
3. Откройте приложение и нажмите **«Запустить прокси»** — появится уведомление о работе в фоне.
4. Нажмите **«Применить в Telegram»** и подтвердите подключение в клиенте.

Поддерживаются официальный Telegram и большинство форков: AyuGram, exteraGram, Plus Messenger, Nekogram, Nagram, Cherrygram, Telegraph и другие.

> [!NOTE]
> Play Защита может предупредить, что «никогда не проверяла приложение этого разработчика». Так она реагирует на любые APK не из Google Play. Нажмите **«Все равно установить»**. Исходный код открыт, а APK собираются публично в [Actions](https://github.com/Alexingin/tg-ws-proxy-android/actions).

> [!TIP]
> Для надёжной работы в фоне отключите для приложения оптимизацию батареи и разрешите автозапуск (на Xiaomi, Huawei, Samsung и т. п. это отдельные пункты в настройках).

## Сборка из исходников

**Через GitHub Actions (проще всего).** Сделайте форк, включите Actions и запустите workflow **Build APK**. Через несколько минут готовые APK появятся в *Artifacts*. Каждый пуш собирается автоматически, а тег вида `v1.2.4` публикует релиз.

Без своего релизного ключа сборка подписывается тестовым ключом из репозитория. Чтобы подписывать своим, добавьте в *Settings → Secrets and variables → Actions* секреты `RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD` и `RELEASE_KEY_ALIAS`.

**Локально на Windows.** Нужны Rust, Android Studio (SDK + NDK):

1. `build_so.bat` — собирает нативную библиотеку движка для arm64-v8a и armeabi-v7a.
2. `build_apk.bat` — собирает APK.

## Сообщить о проблеме

Если прокси отваливается или работает странно:

1. Откройте в приложении вкладку логов сразу после сбоя.
2. Нажмите **«Собрать отчёт»**.
3. Создайте [issue](https://github.com/Alexingin/tg-ws-proxy-android/issues): модель телефона, версия Android, тип сети (Wi-Fi / мобильная) и отчёт.

Единичные ошибки в логах при нормально работающем Telegram — это нормально, на них можно не обращать внимания.
